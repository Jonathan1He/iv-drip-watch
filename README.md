# iv-drip-watch

点滴状态辅助提醒器 MVP。用户在手机浏览器中授权摄像头，把滴斗放入 ROI 检测框，浏览器在本地分析局部画面变化，估计滴速，并在连续一段时间没有有效液滴事件时声音/振动提醒。

## 安全声明

本工具仅为实验性辅助提醒原型，不是医疗器械，不能替代医护人员巡视、诊断或处置。停滴可能由输液结束、管路折叠、堵塞、针头异常、人工暂停等多种原因造成。报警后应立即联系医护人员，不要自行调整针头或输液装置。

它不控制输液装置，不自动夹闭管路，不调节滴速，不做医疗诊断，也不保证发现所有异常。摄像头画面只在当前浏览器内分析，不上传、保存或录制。

## 功能

- 优先请求后置摄像头，支持权限拒绝、无摄像头和设备占用提示。
- 在视频上显示可调整位置、宽度和高度的 ROI 检测框。
- 开始监测时进行约 5 秒背景校准，灵敏度和 ROI 保存到 `localStorage`。
- 将 ROI 缩小到约 64×64 灰度图，计算帧差活动分数。
- 使用平滑、迟滞阈值、合理事件持续时间和防抖状态机识别液滴。
- 显示状态、活动强度、阈值、最近液滴时间、最近一分钟滴数、滑动窗口滴速和总滴数。
- 默认 45 秒无液滴报警，可调 15–180 秒；声音、振动可分别开关。
- 支持测试报警、确认并静音、暂停、停止、重新校准和重置统计。
- 模拟模式支持手动一滴和自动 10、20、30 滴/分钟，不打开摄像头且复用同一套检测/统计/报警逻辑。
- 提供基础 PWA manifest、静态 service worker 和图标占位；不缓存摄像头数据。

## 技术原理

1. `CameraManager` 请求 `getUserMedia`，优先 `facingMode: environment`。
2. 只把 ROI 画到隐藏 Canvas，再缩放为 64×64 并转为灰度数组。
3. `calculateActivityScore` 统计超过像素差阈值的像素比例，得到 0–1 的活动分数。
4. `DropDetector` 对分数平滑；校准阈值使用中位数与 MAD 估计背景噪声；超过高阈值开始候选事件，回落低阈值结束事件。
5. 候选事件必须落在 30–1000 毫秒并通过 500 毫秒防抖，才记为一滴。
6. `calculateDripRate` 清理 60 秒窗口外的时间，用相邻间隔中位数估计滴/分钟。
7. 首次有效液滴后启动停滴计时，达到配置时长触发 `AlarmManager`；报警只由用户确认并静音解除。

## 安装与运行

```bash
npm install
npm run dev
npm run test
npm run typecheck
npm run build
```

`npm run dev` 会启动 Vite 开发服务器。电脑本机的 `localhost` 通常可以测试摄像头；手机访问时应使用 HTTPS 域名。局域网普通 HTTP 地址在多数手机浏览器中不是安全上下文，可能无法取得摄像头权限。部署说明见 [docs/DEPLOY_HTTPS.md](docs/DEPLOY_HTTPS.md)。

## 电脑测试

1. 执行 `npm run dev`，在电脑浏览器打开 Vite 输出的 `localhost` 地址。
2. 点击“打开摄像头”，允许权限；若设备有多个摄像头，应用优先尝试后置摄像头约束。
3. 让滴斗进入检测框，调整 ROI 使其只覆盖液滴通过区域。
4. 点击“开始监测”，保持画面稳定完成约 5 秒校准。
5. 检查活动强度、最近液滴时间、滴速和报警倒计时。
6. 没有合适摄像头时，点击“进入模拟模式”，测试全部控制和报警流程。

## 手机 HTTPS 测试

使用 HTTPS 静态站点打开页面，首次点击“打开摄像头”并授权后置摄像头。将手机稳定固定，不要让页面进入后台；后台浏览器可能暂停 `requestAnimationFrame` 或延迟报警。部署前请阅读 [docs/DEPLOY_HTTPS.md](docs/DEPLOY_HTTPS.md)。

## 模拟模式

点击“进入模拟模式”后不会请求摄像头。点击“开始监测”，再选择自动 10、20、30 滴/分钟或点击“模拟一滴”。点击“停止自动模拟”后等待配置的无液滴时间，可以验证报警；也可以点击“测试报警”直接验证声音/振动和“确认并静音”。

## 已知限制

- 传统帧差分会把反光、灯光闪烁、手机晃动、手或背景移动误认为活动。
- 液滴很小、透明、遮挡严重、背景低对比或帧率不足时可能漏检。
- 不同手机的摄像头曝光、自动对焦和浏览器后台策略不同，阈值需要现场校准。
- Wake Lock、振动和声音受浏览器、系统省电策略和用户权限影响。
- service worker 只缓存静态壳；离线可打开界面不代表离线环境一定能获得摄像头权限。
- 当前 ROI 使用四个滑块，尚未实现触控拖拽缩放；没有真实摄像头自动化测试。

## 后续升级方向

1. 增加触控拖拽 ROI 和实时曲线/录入式误检标记，降低现场调参成本。
2. 用真实手机、多种滴斗和光照样本校准更稳健的自适应阈值。
3. 在不上传视频的前提下增加本地可导出的事件日志和更严格的设备兼容性测试。
