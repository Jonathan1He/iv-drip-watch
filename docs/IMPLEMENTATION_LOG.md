# 实现日志

## 设计选择

- 采用 Vite + TypeScript + 原生 HTML/CSS/Canvas，不引入 React、Vue 或 OpenCV.js。
- 摄像头、Wake Lock、振动、Web Audio、localStorage 和 service worker 均使用浏览器原生能力。
- 核心算法拆为三个可测试模块：帧差活动分数、液滴状态机、滑动窗口滴速。
- ROI 使用归一化 `x/y/width/height`，当前 UI 用四个滑块控制，后续可以替换为触控拖拽而不改变检测接口。
- 真实摄像头和模拟模式都通过同一个 `processFrame`、`DropDetector`、滴速统计和报警流程。
- 报警首次由用户点击开始监测时初始化 AudioContext；报警触发后必须用户点击“确认并静音”。
- 参考 DripOMeter 的“背景校准—事件检测—报警”闭环，以及视觉研究中的两阶段事件思想；没有复制其硬件、模型或云端代码。
- 校准阈值使用中位数 + MAD（median absolute deviation）估计背景噪声，避免一次校准期晃动造成阈值失真，同时保留持续背景噪声抬高阈值的效果。
- 根据首次电脑测试反馈，将默认无液滴报警时间从 45 秒调整为 20 秒；仍允许用户在 15–180 秒范围内自行设置。

## 实际完成步骤

1. 检查工作区和空项目目录，确认没有既有源码或项目级规则。
2. 初始化 Vite、TypeScript、Vitest 和基础目录；创建本地 Git 元数据。
3. 先用占位实现让帧差分测试 RED，再实现像素差比例并 GREEN。
4. 为滴液状态机加入低—高—低、迟滞、持续高活动、事件时长和防抖测试，再实现状态机。
5. 为滴速加入数据不足、稳定间隔、异常间隔和滑动窗口测试，再用中位数实现。
6. 接入摄像头权限、后置摄像头优先、ROI Canvas 灰度采样、5 秒校准和 Wake Lock。
7. 接入模拟模式、声音/振动报警、后台提示、参数保存和中文手机布局。
8. 增加 PWA manifest、service worker 和图标占位。
9. 补齐 README、结构、部署和测试文档。
10. 检索开源/研究参考，补充采用边界文档；为校准离群值和持续背景噪声增加测试并修正阈值算法。

## 关键问题与解决方式

- 普通沙箱运行 Vitest 时，esbuild 子进程返回 `spawn EPERM`；使用受控权限重跑后确认是环境权限问题，测试本身正常执行。
- npm 初始查询/安装遇到用户缓存目录 `EPERM` 和超时；依赖最终安装完成，项目使用本地 `node_modules` 和 `package-lock.json`。
- 受控 Git 初始化产生的元数据权限曾阻止补丁工具；只对本项目新建的 `.git` 修复权限，并清理未提交的临时元数据后继续，源码未受影响。
- TypeScript 首次集成检查发现根节点空值收窄和测试 `filter(Boolean)` 类型问题，已做最小修复。
- 新增校准测试后发现单个高活动离群值会把阈值推高到 0.759；改为稳健统计后，孤立抖动不再压制正常检测。

## 未解决问题

- 尚未在真实手机、真实滴斗和多种灯光下验证误检/漏检率。
- 后台页面可能被浏览器暂停，Wake Lock 也不是所有设备支持。
- Web Audio、振动和 service worker 都依赖浏览器策略；页面提供测试报警但不能替代实机确认。
- ROI 目前是滑块，不是触控拖拽；没有导出本地事件日志。
- 参考项目多为光电硬件、IoT 或深度学习系统，尚未提供与本项目完全等价的浏览器摄像头实现；当前仍需真实设备验证阈值。

## 与初始任务相比的调整

- 没有引入额外依赖；用原生 API 完成摄像头、PWA、音频和振动。
- 没有单独建立复杂的 `appState`、事件总线或组件框架；应用状态集中在 `main.ts`，纯算法保持模块化，符合 MVP 最小范围。
- 帧差分使用超过差值阈值的像素比例，阈值在算法接口中可调；当前 UI 暴露的是灵敏度，校准结果负责生成高/低迟滞阈值。
- 没有把 DripOMeter 的硬件、Smart IV 的云端/闭环控制或 Edge Impulse 的模型引入浏览器，以保持无后端、无上传和不可接触管路的安全边界。
