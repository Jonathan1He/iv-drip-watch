# 测试指南

## 自动化测试

在项目目录执行：

```bash
npm install
npm run test
npm run typecheck
npm run build
```

当前测试覆盖：

- `frameDifference`：相同帧、少量变化、大范围变化、长度不一致。
- `dropDetector`：低—高—低事件、持续高活动、过短、过长、防抖、两次事件。
- `dripRate`：样本不足、稳定间隔、单个异常间隔、窗口过期清理。

## 电脑摄像头测试

1. 执行 `npm run dev`，使用电脑浏览器打开 `localhost`。
2. 点击打开摄像头并允许权限；如果使用了错误摄像头，可在浏览器站点设置中切换后重载。
3. 用滴斗或高对比移动物体做粗测，只把目标经过区域放进 ROI。
4. 点击开始监测，校准期间保持画面不动。
5. 观察活动条是否在目标经过时明显上升，查看滴速和最近液滴时间。
6. 点击测试报警，确认声音；如设备支持，再确认振动。

## 手机实机测试

1. 将构建后的 `dist/` 部署到 HTTPS 占位域名，详见 `DEPLOY_HTTPS.md`。
2. 手机竖屏打开页面，授权后置摄像头。
3. 固定手机，滴斗置于 ROI，点击开始监测。
4. 在校准后观察至少 2–3 分钟，记录滴速显示和真实滴数。
5. 临时停止液滴，设置较短的 15 秒报警时间进行停滴报警验证。
6. 点击“确认并静音”，确认页面从报警状态回到监测状态。
7. 进入后台再返回，检查页面是否显示后台风险提示，并确认 Wake Lock/权限表现。

## 不同光照测试

- 白天自然光、室内稳定光、低照度、背光、局部反光。
- 每种环境先重新校准，再记录 2 分钟误检和漏检。
- 特别观察灯光闪烁、自动曝光变化是否制造高活动分数。

## 晃动和背景干扰测试

- 固定手机与手持手机各测试一次。
- 在 ROI 外移动手、输液架和人员；在 ROI 内放入手指或反光物做压力测试。
- 轻微移动滴斗位置，确认提示用户重新调整 ROI，而不是把背景变化当成液滴。
- 记录误检发生时的活动条、阈值、ROI 和光照条件。

## 如何记录漏检和误检

- 漏检：真实液滴经过但总滴数未增加；记录本地时间、实际滴序号、画面/光照/手机型号。
- 误检：没有真实液滴但总滴数增加；记录触发前后的背景动作、活动分数和当前阈值。
- 不保存或上传摄像头视频；如需要证据，只记录不含视频的参数、时间和文字描述。
- 每次改变 ROI、灵敏度或报警时长后重新开始一轮，并在记录中标注配置。

## 验收边界

自动化测试通过只说明纯逻辑模块满足当前人工序列测试，不代表医疗级准确率。真实验收必须包含手机实机、稳定固定、不同光照和背景干扰，并由用户/医护人员判断是否适合辅助使用。
